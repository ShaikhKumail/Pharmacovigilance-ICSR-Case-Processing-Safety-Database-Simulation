# Pharmacovigilance ICSR Case Processing & Safety Database Simulation

## 📌 About the Project

This project is a **synthetic Individual Case Safety Report (ICSR) case-processing and safety database simulation** developed to demonstrate practical understanding of entry-level Pharmacovigilance case-processing activities.

The project contains **20 synthetic ICSR cases** and follows a structured workflow covering case intake, triage, duplicate assessment, case data entry, medical coding, follow-up, narrative writing, and quality control.

The purpose of this project is to simulate how an entry-level Pharmacovigilance professional may process and review safety case information in a structured environment.

> **Important:** All patient, reporter, product, event, and case information used in this project is fictional and created strictly for educational and portfolio purposes.

---

# 🧪 What is an ICSR?

An **Individual Case Safety Report (ICSR)** is a report containing information about an individual patient who has experienced one or more adverse events or suspected adverse reactions associated with the use of a medicinal product.

ICSRs may originate from different sources, including:

- Healthcare professionals
- Patients or consumers
- Regulatory authorities
- Literature
- Clinical studies
- Market research or patient-support programs
- Other authorized reporting sources

ICSR processing is an important part of Pharmacovigilance because accurate and consistent processing of safety information supports ongoing monitoring of the safety profile of medicinal products.

---

# 🔎 Minimum Criteria for a Valid ICSR

Before processing a report as a valid ICSR, the available information is assessed for the basic case requirements.

The project considers the following four key elements:

1. **Identifiable patient**
2. **Identifiable reporter**
3. **Suspect medicinal product**
4. **Adverse event or observation**

If essential information is missing, the report may require clarification or follow-up before it can be considered a valid case.

---

# 🔄 ICSR Processing Workflow

The project follows the workflow:

**Source Report → Intake & Triage → Duplicate Assessment → Case Processing → Medical Coding → Follow-up → Narrative Writing → QC**

Each stage represents an important activity in the ICSR case-processing workflow.

---

## 1. 📥 Source Report & Case Intake

The process begins when a safety report is received.

Important information is identified from the source report, including:

- Patient information
- Reporter information
- Suspect medicinal product
- Indication
- Adverse event
- Event onset information
- Seriousness
- Outcome
- Action taken with the suspect product
- Dechallenge and rechallenge information
- Relevant clinical information

The available information is then prepared for structured case processing.

---

## 2. 🚦 Intake & Triage

During triage, the available report is reviewed to determine whether it contains the information required for case processing.

The review includes:

- Validity assessment
- Seriousness assessment
- Source identification
- Initial report vs follow-up report
- Important missing information
- Need for follow-up
- Potential duplicate cases

Triage helps ensure that cases are processed consistently and prioritized according to applicable procedures.

---

## 3. 🔍 Duplicate Assessment

Duplicate assessment is performed to determine whether the incoming report may represent a previously received case.

Potential duplicate indicators may include:

- Similar patient information
- Same or similar suspect product
- Similar adverse event
- Similar event timing
- Same or similar reporter
- Similar clinical circumstances

Potential duplicates are reviewed carefully rather than automatically treated as duplicates.

---

## 4. 📝 ICSR Case Processing

Once a report is identified for processing, relevant information is entered into structured case fields.

The project includes information such as:

### Patient Information
- Case ID
- Patient age
- Patient sex

### Product Information
- Suspect product
- Indication
- Action taken with product

### Event Information
- Adverse event
- Event onset
- Seriousness
- Seriousness criterion
- Outcome

### Clinical Information
- Dechallenge
- Rechallenge
- Relevant treatment/intervention
- Reporter information
- Reporter causality opinion

The objective is to demonstrate structured and accurate transfer of information from the source report into the case-processing record.

---

# 5. 💊 Medical Coding

Medical coding is an important part of ICSR processing.

In Pharmacovigilance, adverse events are commonly coded using **MedDRA (Medical Dictionary for Regulatory Activities)**.

The project includes a dedicated coding section for recording the relevant coding information.

The focus of this project is to demonstrate the **coding workflow and structured handling of coding information**, rather than claiming access to a commercial safety database or licensed MedDRA environment.

---

# 6. 🔄 Follow-up & Case Updates

Follow-up may be required when important information is missing or additional information becomes available.

Examples of information that may require follow-up include:

- Missing outcome
- Additional clinical details
- Laboratory results
- Treatment information
- Action taken with the suspect product
- Dechallenge/rechallenge information
- Additional reporter information

When follow-up information is received, the case is updated while maintaining the distinction between the initial report and subsequent information.

The project includes examples of follow-up cases and pending follow-up requests.

---

# 7. 📖 Narrative Writing

The case narrative provides a concise chronological summary of the available case information.

A structured narrative may include:

- Patient information
- Suspect medicinal product
- Indication
- Relevant medical history when available
- Event and event onset
- Clinical course
- Relevant treatment/intervention
- Action taken with the suspect product
- Dechallenge/rechallenge information
- Outcome
- Reporter causality opinion when provided

The objective is to ensure that the narrative accurately reflects the information contained in the source report.

---

# 8. ✅ Quality Control

Quality control is performed to verify consistency and accuracy across the processed case.

The project includes checks between:

**Source Report ↔ Case Processing ↔ Coding ↔ Follow-up ↔ Narrative**

Examples of QC checks include:

- Patient information consistency
- Product information consistency
- Event consistency
- Seriousness consistency
- Outcome consistency
- Action taken consistency
- Follow-up information consistency
- Narrative consistency
- Coding information consistency

QC helps identify missing, inconsistent, or incorrectly transferred information before case completion.

- QPPV responsibilities
- Safety Data Exchange Agreement management

These areas are important parts of the broader Pharmacovigilance function but are outside the intended scope of this entry-level case-processing project.
